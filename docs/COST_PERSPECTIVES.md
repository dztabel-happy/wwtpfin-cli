# 成本、合同支付与指定主体净支出

“降低建设期和运营期总成本”需要先分清项目花多少钱、合同付多少钱、指定主体最终承担多少钱。四种视角引用同一次计算的逐期底账，不改变原财务报表、税额、现金流或偿债结果。新选定成果必须用决策合同的 `cost_goal` 绑定实际降本目标，再以其生成的决策成本比较；旧指标仍可用于探索和辅助分析。

| 指标前缀 | 纳入范围 | 主要限制 |
|---|---|---|
| `investment_opex_outlay` | 不含建设期利息的初始投资 + 运营期资本支出 + 含税经营支出 | 含存量取得价款，非社会资源成本；投资按输入声明的现金金额列示 |
| `project_cash_cost_net` | 初始投资及建设期利息 + 运营资本支出、经营、融资费用、实际现金税费、流动资金投入 − 流动资金回收、退税、期末实际变现现金 | 不扣营业收入、补助；不重复计贷款本金、资本金或摊销。融资不可唯一重建时为空 |
| `service_grant_payment` | 含税服务费 + 实际到位资本补助 | 不含副产品收入与期末支付；不是财政净负担 |
| `payer_net_outflow` | 按明确比例归属服务费、补助、期末支付 + 另列支出 − 另列收入 | 仅对应指定主体、声明范围；未建模或范围不完整时为空 |

每个前缀有 `_wan`（名义合计，万元）和 `_npv_wan`（现值，万元）两个指标。现值为 `sum(C[i] / (1 + discount_rate)^t[i])`，其中 `t[i]` 来自 `time_axis.cashflow_times_years`；第 0 期不折现。建设期与运营期按实际期间归集：明确 `time_basis` 后支持月精度的非整年期限，在自然年度与阶段边界分期，期内现金汇总到所属期末，并按实际经过年数折现；这不是逐日收付明细。

初始投资的 `capex_schedule_wan`、资产及重置投资的 `cost_wan` 按声明的投资现金金额输入。`net_of_deductible_vat` 不会自动把这些付款改为不含税金额：显式 `deductible_vat_wan` 从资产计提基数扣除，并进入进项税及留抵台账，不直接减少建设付款、建设期利息或债股筹资。例如含税付款 109 万元、可抵扣进项税 9 万元，应列投资现金 109、可抵扣税额 9；资产基数为 100（建设资产另加分配的资本化利息），不能先将现金输入净额化为 100 后再扣同一笔 9。工程发票或财政预算审计仍需对应现金与税务底稿。

各视角不能相加；合同支付已为项目支出提供资金，重复相加会重复计算。既有 `total_lifecycle_cost_wan` / `total_lifecycle_net_cost_wan` 保留原评价定义兼容旧成果，后者扣除的是评价余值，不能改称真实现金净成本。

## 从业务目标到机器目标

用户说“建设和运营总成本”，通常应先用 `project_cash_cost_net` 解释项目实际建设、运营、更新、财税融资和流动资金的净支出，再说明其中不扣营业收入与补助。若用户要比较较窄的投资与经营支出，才用 `investment_opex_outlay` 并明确排除的费用；它包含存量取得价款，也不能直接命名为社会资源成本。合同支付与本级财政负担可以另列，但不能自动替换用户的项目成本目标。先依据用户原话和项目决策范围说明所选视角；不靠示例文件替业务人员决定目标。

`decision-contract.cost_goal` 的字段如下。它可暂缺以开展旧式试算，但缺失或审查不完整时不能新建选定成果。

| 字段 | 约束 |
|---|---|
| `statement`、`evidence_refs` | 实际业务目标及非空依据引用；引用须唯一解析到绑定证据的 supporting 记录。 |
| `perspective` | 上表四种视角之一；机器范围由此决定，不从自由文字推断。 |
| `valuation` | `nominal` 或 `present_value`。 |
| `horizon_years` | 从共同项目起点到共同服务终点的总年数，含建设期，须可表示为整月。 |
| `discount_rate` | 有依据的有限非负共同折现率，与基准和候选估值一致。 |
| `requirements` | 分别登记 `service`、`compliance`、`investment_return`，不能遗漏后两项以省去约束。 |

每条 requirement 必须有 `topic`、`status`、`constraint_metrics`、`condition_ids`、`basis`、非空 `evidence_refs`。`service` 与 `compliance` 必须为 `required`，并引用合同中真实存在的 `required_conditions`；可计算边界另关联实际 `hard_constraints`。投资回报若为 `required`，须关联真实收益率或 NPV 的 `>` / `>=` 下限，不能用资本金比例或现金非负代替回报要求；确实不适用时以 `not_applicable` 说明依据，不能照搬另一种实施模式的收益率，也不能借此取消本项目实际需要的投资者回报。所有条件 ID、约束指标与证据 ID 都须能解析，CLI 只核引用及契约关系，不认证业务分类正确。

合同及方案集的主目标必须一致：`nominal` 对应 `objective.metric: decision_cost_wan`，`present_value` 对应 `decision_cost_npv_wan`，均为 `direction: min`；`comparison_basis.unit` 必须为“万元”。`comparison_basis` 仍解释范围与口径，不能靠文字把窄指标改名为完整成本。`decision_review.canonical_basis` 给出实际机器视角、单位、期间和折现尺。可选次级目标及绝对并列容差按[研究契约](RESEARCH_REVIEW.md)使用，不得放宽硬约束。

绑定 `cost_goal` 后，CLI 保留累计资金非负、完整模型及合同显式数值约束的门槛，**不把所有债务的现金 DSCR≥1自动作为硬约束**。真实累计资金缺口、融资无法唯一计算或合同明定的 DSCR 下限不满足，仍不能凭条件确认或用户偏好进入选定成果。贷款人或用户实际规定的 DSCR 要求应登记到 `hard_constraints`，不能因为模型期初有余额而取消该约定。

当期经营现金不足以覆盖本息、但完整累计现金闭合且没有违反显式约束时，`financing_review` 允许条件研究，自动加入原合同的 `financing_cash_availability` 或续期的 `continuation_financing_cash_availability`。由项目实施主体、资金提供方及贷款人核验既有结余和其他已建模资金的实际可用性、用途限制、到位时点、分配安排及融资协议。候选可在 `conditions` 中用这些自动 ID 记录状态，无须虚构另一项资金来源。实施选择要求该触发条件为 `satisfied` 且证据引用有效；`not_applicable` 不能豁免真实触发，保持待落实。其他研究与实施门禁仍照常执行。

审查逐期保留期初/期末模型余额、当期经营可偿债现金和本息缺额。它不把期初余额、新借款或补助加进现金 DSCR 分子，也没有建立受限存款或偿债储备账户模型；利润分配中的盈余公积不等于可用偿债现金。累计非负仅是算术衔接，不能推断银行批准、储备账户成立或付款时点必然可行。条件研究不能豁免真实资金缺口，已满足的证据引用也不认证协议解释的真实性。

`terminal_asset_event: continued_use` 表示评价期结束后资产继续使用。`TERMINAL_VALUE` 可按明示方法列评价余值；`TERMINAL_CASH_RECOVERY` 和 `terminal_cash_recovery_wan` 则为零。实际资金余额、`project_cash_cost_net` 及付款方期末支付只计真实回收；不能把账面净值另行填入 `payer_cashflow.other_cashflows` 伪装成结存返还。处置/移交使用 `disposal`，仍须说明是否实际有收付和对手方。显式运营流动资金回收计划是单独事件。

`net_book_value` 的既有范围为资本资产组，包含建设/取得资产、更新资产及建设期存货；不是期末账户现金与全部流动资产的合计。独立 `operating_working_capital[]` 按其实际回收声明和期末占用单列，不自动再加入该评价余值。其 `recover_operation_year: null` 明确表示期内不回收：资金占用和流动资产仍在，回收现金为零，不因 `disposal` 经另一现金通道加回。显式期内回收仍按原安排计算，不会与评价余值重复计入。保留资金会影响相关投资评价与真实现金指标；不能把继续占用解释成已经变现。

## 指定主体收支输入

`payer_cashflow` 是可选输入。省略或 `{}` 表示未建模，净支出指标为 `null`。完整对象须同时提供：

- `entity`、`scope`、`basis`、非空 `evidence_refs`：主体、收支范围及依据。
- `coverage: partial | complete`：范围是否完整的输入声明，CLI 不代替审核人认证。
- `service_payment_share`、`capital_grant_payment_share`、`terminal_payment_share`：0 至 1 的支付归属比例，不根据结算渠道自动推断。
- `other_cashflows`：另列收支，每项包含唯一 `id`、`label`、`direction: inflow | outflow`、`amounts_wan`、`basis`、`evidence_refs`。金额为有限非负数，长度必须等于 `len(time_axis.cashflow_times_years)`，包括第 0 期；也就是 `1 + len(construction_period_years) + len(operation_period_years)`，不能将建设或运营年数直接当作期数。每项是对应期间总额，不因不足一年再次缩放。服务费、补助、期末价款已自动归属，不得重复计入另列收支。

例如政府代收用户污水处理费再支付运营方，应分别列服务费支付与代收收入。收款范围、时间和金额缺失时保留 `partial`，输出已列收支底账；不能升级为完整净支出目标。税费不自动抵扣为同一主体收入，借款也不自动成为降本收入。外部收支及适用范围仍需业务人员核实。

有依据的估算可开展明确的条件情景，范围完整不代表金额已核定。估算边界与落实条件进入证据和决策合同，不用等全部资料核定才进行探索。

## 同一服务期间的比较

候选须具有相同项目开始年月和投运时点，按共同时间轴逐段核对实际处理水量。当前不支持用不同投运时点、尚未建模的过渡服务直接比较。出水标准、可靠性及未数值化的服务要求仍由固定参数、实施条件和真实依据约束；同水量不证明工程服务等效。

同期限可以使用四种成本视角。**不同合同期限的完整比较目前仅支持 `payer_net_outflow`。**共同终点不得短于任何原合同终点；指定主体及责任范围在基准、候选和续期中相同，且收支声明完整。不能截掉长合同的末期支付、把短合同结束后的服务填零，或按平均年费、等额年成本外推后声称比较已完成。目标为其他视角而现有能力不能表达不同期限时，披露能力边界，不能为让 CLI 通过擅自改成付款方目标。

短合同候选在方案集自身条目提供 `continuation: {params, basis, evidence_refs}`；比较基准也短于共同终点时，在方案集顶层提供 `base_continuation`。`params` 是按 input schema 填全的独立续期模型，不是原模型的局部覆盖。它须在原合同到期年月立即开始、`capital.construction_years: 0`，其完整期限恰好到达共同终点；服务、成本、更新、税务、融资、收支与期末安排均须显式建模。原合同的期末责任保留，续期初期资金及资产安排须另有依据，不能假定原合同余额或资产无偿转入。

CLI 分别完整计算原合同与续期，将每笔成本按实际相对时点合并，以同一 `cost_goal.discount_rate` 折现。续期内部检查、模型范围、融资与累计现金须闭合；不额外施加普遍的账面或现金 DSCR≥1门槛，按上文融资审查区分真实缺口、合同显式约束与现金可用性条件。合同中登记的投资回报、现金/偿债和资本金比例等财务下限同时检查续期，不因进入第二份模型而失效。续期依据、原/续期付款方及另列收支引用不可缺失、重复或仅指向 unresolved；坏引用不能支撑推荐或选择。源码检查引用和计算一致性，费用估算、资产交接与资格适用的真实性仍需 Agent 审查。

续期安排必须参加[共同情景研究](RESEARCH_REVIEW.md#续期也属于研究对象)，不能只压力测试原合同。改变服务、目标或折现尺需要重建相应决策范围，不是给某候选降低服务或更换折现率的情景。

## 比较与成果

`tariff_blended_gross` 只在服务费计取函数与补助序列不变时可作探索性的支付代理。补助、计费量、调价、阶梯机制变化时应改用完整支付指标，不能凭起始单价较低声称总成本较低；新选定成果仍须使用上述决策成本主目标。`numerically_feasible`、`comparable`、实施条件与用户选择分别记录；`feasible` 同时要求数值及可比口径通过。`decision_review` 与 `research_review` 都须通过对应门禁，不能仅看候选排序。未满足可比范围的结果可保留诊断，不生成权威决策总额或可选排序。

通用反例：单价从 4.00 降至 3.99 元，同时增加 1,000 万元资本补助；服务费减少 254.5875 万元，合计支付增加 745.4125 万元。产品阻止用单价对该变化直接排序，按完整支付可正确比较。此算例是产品验收，不是政策建议或项目报价。

`result.json.costs` 保存逐期组成、口径说明与主体收支，`scalars` 保存 8 个指标。成果包增加正文用途的 `cost_perspectives` 表及工作底稿用途的 `cost_cashflows`、条件生成的 `payer_cashflows`；方案比较同时列各候选的成本口径。

选定运行另生成 `cost-comparison.json` 和 `cost-cashflows.csv`，记录共同服务期成本及逐笔合同归属、期次和时点。有续期时，`deliverable/` 是原合同完整计算，`continuation-deliverable/` 是续期完整计算；续期仅继承明确引用的 supporting，不继承原项目证据中的声明指标或决策，并由 `continuation_context` 标明独立计算范围。`final-run.json` 将两份成果与共同底账一起绑定，`verify-final-run` 重核。共同期间总额用于成本决策，不能冒充原合同或续期各自的收益率、现金结余。摘要与正式报告须标出成本视角、比较基准来源、共同期间和条件；估算建立的基准不能简称为原报告已经给定的总成本。

## 制度背景与能力边界

2024 年《基础设施和公用事业特许经营管理办法》第六条区分直接收费与政府等代收，第十四条涉及全生命周期成本比较，第二十二条对代收转付和政府投资支持规定相应条件。这支持分开核算收入来源、支付路径和成本，不意味着任意财政支持方案均被允许。[国家发展改革委公布原文](https://zfxxgk.ndrc.gov.cn/web/iteminfo.jsp?id=20369)

本模块计算已声明机制，不判断政策资格、不建立全口径政府预算、不自动设计融资、不证明全局最优。任意多变量搜索、期内逐日收付或运营期股东增资仍须按实际支持边界处理。
