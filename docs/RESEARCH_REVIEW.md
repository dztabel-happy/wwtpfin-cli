# 研究与推荐约束

第二阶段的责任是从同一事实与目标出发，主动研究有依据的措施，测试会改变选择的假设，给业务人员一份可以判断的建议。一个正常案例内可以多次检索、比较和重算；不要求用户重开任务、点名政策或指出遗漏之后才补研究。

CLI 对有限候选进行确定性计算并核对已登记的研究。它不判断原文真伪、政策是否实际适用、工程方案是否穷尽，也不证明全局最优。研究记录通过不是专业判断的替代品。资料仍不足时，应给出已测的条件分支与下一步取证价值，不编造唯一最优方案。

## 与现有三阶段的关系

第一阶段准备参数、证据和含 `cost_goal` 的独立决策合同；第二阶段在方案集增加 `research`，由 `compare` 输出成本目标审查 `decision_review` 和研究审查 `research_review`；第三阶段在用户明确选择后，沿用 `finalize` 完整重算与历史绑定。没有新增阶段或新增 skill。资料、目标或关键假设改变时返回前阶段，当前入口与旧成果处理沿用[案例工作流](CASE_WORKFLOW.md)。

```bash
wwtp-fin schema --kind scheme-set
wwtp-fin schema --kind decision-contract
wwtp-fin schema --kind scheme-selection
wwtp-fin compare -p input/project.yaml --contract input/decision-contract.yaml --evidence input/evidence.json --schemes comparisons/compare-0001/scheme-set.yaml -o comparisons/compare-0001/output
```

以当前安装版本导出的 schema 为字段权威。旧的无 `research` 方案集或无 `cost_goal` 合同仍可试算，比较会明确显示尚未完成对应审查，不能借数值排序直接进入新选定成果。

## 先明确如何判断“更好”

决策合同的 `objective` 是主目标，可选的 `secondary_objectives` 为至多三项有序次级目标。每项使用 `metric`、`direction`、`basis`，可选非负绝对 `tolerance`，单位与该指标一致，缺省为零。

新选定成果的 `cost_goal` 必须明确真实业务目标、四种成本视角之一、共同服务期间、折现率及服务/合规/投资回报要求。名义值主目标为 `decision_cost_wan`，现值为 `decision_cost_npv_wan`，均最小化且单位为万元。自由文字不能把较窄支出改称全成本，也不能把建设运营降本偷换为财政支付下降。服务与合规关联真实实施条件；回报适用时关联实际收益率或 NPV 下限，不适用时保留依据。字段与范围见[成本契约](COST_PERSPECTIVES.md#从业务目标到机器目标)。

每次比较先保留与当轮主目标最优值相差不超过其 `tolerance` 的候选，再对这一组按次级目标依次处理。最后仍可有并列。容差是有依据的无差异范围，不能改变硬约束、补救计算错误或为指定候选放宽标准。多个目标不跨口径相加，也不暗设权重；未登记的次级目标不用于自动打破并列。

候选列表、CLI 摘要与每个研究情景共用这一排序算法。`ranking_groups` 按优先顺序列出并列组，`shortlist` 仅将各组展开；同组按 ID 排列是稳定展示，不构成偏好。`best_candidates` 是完整首组；旧字段 `best_by_objective` 仅在首组唯一时给出 ID，并列时为 `null`。这些字段描述本情景内的数值排序；研究情景还排除模型未闭合候选，实际推荐须继续检查共同情景与实施条件。

主目标、服务边界和硬约束保持一致。降低资源投入、降低项目资金支出和改变财政支付时点可能是不同结果；若实际推荐依赖其中另一项，应在比较前说明主次与取舍并更新合同，不能算完后更换判据。

完整降本比较保留真实累计资金缺口、模型缺口及合同显式数值约束的阻断，不对所有有债务候选自动施加现金 DSCR≥1，也不对续期普遍施加账面 DSCR≥1。当期经营现金不足但累计现金闭合、显式约束通过时，可研究有条件的资金安排，自动生成 `financing_cash_availability` / `continuation_financing_cash_availability`。实施选择须由责任方以有效证据登记为 `satisfied`；真实触发不能写成 `not_applicable` 规避。必须核实结余可用性、受限用途、分配与融资条款，不能把累计非负当作贷款批准或已建储备账户。详见[成本与融资审查](COST_PERSPECTIVES.md#从业务目标到机器目标)。

## `research` 输入

`research` 由 `directions`、`assumptions`、`scenarios`、`combinations` 和非空 `stopping_reason` 组成。它直接放入当前方案集，供计算与选择绑定，不再要求另建一套同内容台账。来源文件和工程推导仍保留在原有证据与底稿中。

四类条目的 `evidence_refs` 均须唯一解析到本次绑定 `evidence.supporting[].evidence_id`。只写一个文件名、URL或不存在的编号不等于登记证据；先把实际原文、估算底稿或计算记录放入 supporting，再引用其 ID。缺失、重复或仅在 unresolved 中的引用使 `research_evidence_review.passed=false`，保留计算而阻止收口。普通估算可继续标为 `unverified`，不要求伪装成已核验事实，也不要求全部材料使用下述严格来源快照。引用可解析不证明原文理解、估算方法或政策适用正确。

`user_bound: true` 只用于用户实际固定的设计选择；其全部关联路径和值必须同时由决策合同 `fixed_parameters` 覆盖，基准与候选保持相同。完整成本决策还要求该项引用的用户原话快照逐叶登记 `scope.parameter_values`，见下文。合同中锁定同值只保证比较边界，不自动免除取值分类和方案研究。

### 方向及措施

`directions[]` 每条包含 `id`、`domain`、`status`、`candidate_ids`、`paths`、`basis`、`evidence_refs`，结构排除另带 `exclusion`。六个通用域均需处置；同一域可以有多条具体方向：

| `domain` | 审查问题 |
|---|---|
| `service_demand` | 服务范围、处理量、负荷与质量要求是否理解正确，有无有依据的需求或时序方案？ |
| `capital_and_renewal` | 建设规模、工程组织、设备更新与期末处理是否有可研究的替代？ |
| `operations` | 能耗、药耗、人员、维护及处置方式有哪些可验证的改进？ |
| `tax_and_support` | 税费与支持政策是否有效且适用，金额、时序与资格条件怎样影响方案？ |
| `financing_and_payment` | 融资、还本、拨付和资金安排是否闭合，是否影响已声明目标及风险？ |
| `delivery_and_contract` | 实施模式、服务分工、采购和合同责任是否提供可执行的替代？ |

`status` 使用 `evaluated`、`excluded`、`open` 或 `not_applicable`。数值较差、收益较小或暂不采用的方向仍为 `evaluated`：关联完整反事实候选、实际变化路径和共同情景，保留为什么不选它的计算。关联路径须在至少一个关联候选或共同情景中相对该情景基准实际变化；候选不能有计算错误、未支持模型、不可比口径或缺失目标值。真实算出的硬约束失败可以保留为有用反例，不应伪装成结构排除。`excluded` 和 `not_applicable` 仅用于来源支持的结构排除，须提供下述 `exclusion`，不能拿某单项表现不好代替。仍有待研究的有价值方向保持 `open`。六域是检查覆盖面的提示，不是固定杠杆目录或每案必须生成六套方案的数量要求。

`paths` 记录该方向解释的规范化参数路径，数组项可用数字索引；应尽量贴近实际变化。候选相对基准的每项参数变化，必须由关联的已研究方向路径或下面的假设路径解释。不要用过宽父路径掩盖无关变化。

研究是否被实际行使，按参与计算的输入差异判定。仅改项目名称、来源说明、展示精度或其他展示元数据，不能充当措施、有效情景、设计变体或已测组合；输入中名称引用的真实计算关联仍须保留。反之，税率、现金安排等真实计算参数已改变，即使当前基数为零导致输出恰好不变，也属于有效测试，不能仅凭结果差为零将其抹除。研究用模型身份与完整审计哈希分开：展示或来源修正仍须遵守当前性与重新绑定规则，但不因此凭空产生一项财务措施。

### 结构排除与来源快照

`excluded` / `not_applicable` 方向，以及 `result_candidate_id: null` 的组合，在收口时需要 `exclusion`。对象包含：

| 字段 | 含义 |
|---|---|
| `kind` | 固定为 `source_rule`；来源支持的法律、合同、工程或其他结构限制。 |
| `scope_candidate_ids` | 排除所适用的真实候选 ID。方向须覆盖本轮全部候选（含自动加入的 `base`）；组合须恰好对应该条的 `candidate_ids`。 |
| `applicability` | 来源规定如何对应本项目事实、实施主体或参数安排。 |
| `exceptions` | 相关允许安排、例外和处理说明；没有适用例外也须说明核查结果。 |

新增候选会改变方向排除的范围，不能静默继承旧判断。范围字段只是机械核对范围声明，不能使过宽的解释变得成立。一个来源只限制某种融资或实施安排时，不能直接排除同名政策或模式的全部变体。

完整成本决策的方向排除还核对 `source_snapshot.value.scope`。`authority` 为 `source_rule` 或 `user_requirement`；`parameter_paths` 列出原文实际限制的参数叶路径，`parameter_values` 逐叶记录用户明确固定的参数值，`contract_values` 单独记录评价合同的要求。三个字段至少一个非空；非空对象、数组须逐叶登记，不能用一个父路径声称全部子项已被来源排除。方向中的父路径会按基准和候选展开，再逐一检查来源范围。尚未配置、但研究清单触发的机制直接登记其完整机制路径。

例如用户只要求“共同评价30年，采用3.5%折现率”，快照可记录 `scope: {authority: user_requirement, contract_values: {cost_goal.horizon_years: 30, cost_goal.discount_rate: 0.035}, parameter_values: {discount_rate: 0.035}}`。这不包含 `concession_years`、续期或期末处理方式，因此不能据此停止期限及交接安排研究。每项 `user_bound` 必须引用真正约束它的用户快照（可通过该项 `parameter_basis.source_refs`），不能借另一项的引用补足。

`research_review.scope_constraints_review` 核对当前引用、参数范围和值；`verified_fixed_parameters` 仅列有用户来源且与合同、基准、候选同值的精确叶路径。其余输入继续需要事实、估算或设计分类，不能仅写入 `fixed_parameters` 绕过。程序不认证登记者对原话的解释：原文只说30年时，擅自将27.5年合同写进用户范围仍是错误登记，需要专业审查。

`exclusion` 沿用该方向或组合的 `evidence_refs`，其中每项都必须解析到 `evidence.supporting[]` 的来源快照；不能混入只有标题或未取得正文的所谓支持证据。普通推理写在 `basis`，所依赖的工程、合同原文也可以登记快照。支持排除的记录使用 `value.type: source_snapshot`：`text` 是保存的连续完整来源正文，`sha256` 是该正文 UTF-8 字节的 SHA256；`citation` 包含 `start`、`end`、`text` 和 `locator`。引文区间按 Python Unicode 码点计数、左闭右开，`citation.text` 必须等于正文的精确切片，定位说明为条款、页段或表格位置。原有 `source`、`as_of` 等元数据保留在 supporting 记录外层。排除证据须有非空来源定位，以及按来源实际精度填写的 `YYYY-MM` 或 `YYYY-MM-DD` 日期；不能用抓取日冒充文件生效日。

下面从已取得的 UTF-8 来源文本及核对过的引文范围生成 `value`，不会生成项目适用性判断。命令参数依次为来源文本路径、起止码点和定位说明：

```python
from pathlib import Path
import hashlib, json, sys

text = Path(sys.argv[1]).read_bytes().decode("utf-8")
start, end = map(int, sys.argv[2:4])
assert 0 <= start < end <= len(text)
value = {
    "type": "source_snapshot",
    "text": text,
    "sha256": hashlib.sha256(text.encode("utf-8")).hexdigest(),
    "citation": {
        "start": start, "end": end,
        "text": text[start:end], "locator": sys.argv[4],
    },
}
print(json.dumps(value, ensure_ascii=False, indent=2))
```

来源正文应来自实际取得的原文或附件，保留完整相关条款及限定语；不能把摘要或 Agent 自写结论改名为原文。CLI 不要求另设外置文件路径字段，只检查嵌入记录存在、正文哈希、引文切片及范围声明一致，不认证正文真实性、法律效力、上下文是否充分或适用解释正确。政策存在和项目资格成立仍是两件事。缺附件、条款未读或含义未决时可继续条件试算，不能据此关闭另一条路径。

### 原始文件与摘录绑定

新完整成本研究中，实际引用的外部 `source_snapshot` 还须提供 `artifact`：`path`、原始文件字节的 `sha256`、版本化 `extractor` 和 `selector`。用 `source-snapshot` 直接产生快照，避免自行改写原文后仅对改写文本计算哈希。省略 `--selector` 时只列位置与截断预览；预览不能用作正式摘录。

```bash
wwtp-fin source-snapshot sources/report.docx --extractor docx-body/1
wwtp-fin source-snapshot sources/report.docx --extractor docx-body/1 --offset 100 --limit 100
wwtp-fin source-snapshot sources/report.docx --extractor docx-body/1 --selector '{"start":12,"end":15}' --evidence-dir input
wwtp-fin source-snapshot sources/policy.html --extractor html-element/1 --selector '{"tag":"table","index":0}' --evidence-dir input
```

位置示例须换成实际文件的位置。`docx-body/1` 按 `word/document.xml` 正文顶层段落和表格编号，选择零起始半开范围；保留物理表格行列，不复制合并格金额，也不推断页码。`html-element/1` 定位已保存静态 UTF-8 HTML 中受支持标签的第 `index` 个元素，不执行脚本或联网。返回的完整提取文本必须与快照 `text` 完全一致，再核正文哈希及引文切片。保持表头、单位及相关限定语的上下文；真实数字存在不等于业务含义正确。

活跃输入的 `artifact.path` 始终以 `--evidence` 文件父目录解析，不能猜当前工作目录。Python 调用带原件的输入时显式给 `source_base_dir`。比较保存原 evidence 和 `sources/<文件摘要>.bin`；成果包也保存自己引用的原始字节。最终主成果承担完整研究来源归档，续期成果只保存其携带的来源。归档验证按摘要读取包内原件，搬离旧工作区后仍可离线提取；缺失、变更或包外链接不回退到原路径或网络。比较后原文件改变，即使 evidence JSON 未改，也须重新比较与确认。

`source_artifact_review` 独立记录文件提取是否复现。完整研究的引用包括研究条目、成本目标、实际模型及条件、付款方收支和续期证据，并沿用 `parameter_basis.source_refs` 一跳；外部事实、估算输入和来源排除不能靠删掉 `artifact` 恢复通过。真实用户对话只用于目标合同或有相同取值锁定的参数约束时，可以保留对话身份，不能冒充文件已核验；把同一对话记录用于外部数值推导，不能仅凭 `authority` 豁免原件。

普通 `build` 不要求研究收口，但已声明的原件绑定必须真实成立。未支持的来源格式须如实保留未机械绑定状态；条件测算仍可开展，不能声称完整研究来源门禁通过。不得把自写摘要另存为 HTML/Word 冒充原始资料。旧成果缺少新标记时保留历史验证语义；新创建始终检查新绑定，新包存在标记或原件声明却缺审查不能降级为历史豁免。

这些检查证明保存字节到摘录的复现，不证明发布者身份、完整上下文、选列、总额与子集关系、政策效力或项目适用性。估算底稿和专业解释仍须单独审查，不能用算术正确代替原文含义正确。

### 事实、估算与设计选择

`assumptions[]` 每条包含 `id`、非空 `paths`、`kind`、`basis`、`evidence_refs`、`material`、`scenario_ids`，可选 `user_bound`。`kind` 为 `source_fact`、`estimate` 或 `design_choice`。

来源事实必须保留范围和限定语。设计能力不等于年均处理量，整体成本不等于新增项目成本，资产寿命不等于项目日历年份。**报告中出现的未来水量、价格或成本预测，仍是估算，不因写进可研便成为确定事实。**原文没有建立所需含义时，估算须说明推导方法，不能仅引用原文件名便把推导结果归为事实。缺少 Excel 不阻止基于工程量、适用定额、地区价格或明确研究提案开展测算。

完整降本决策中，`source_fact`、`estimate`、`design_choice` 均必须在该假设的 `evidence_refs` 中引用 `supporting.value.type: parameter_basis`，不能只改 `kind` 逃过重要估算的研究门槛。该值包含：

| 字段 | 绑定要求 |
|---|---|
| `type` | `parameter_basis`。 |
| `kind` | 与引用它的假设分类相同。 |
| `baseline_values` | 对象，键为真实点路径，值为当前已解析基准中的完整值；包括需要时的 `continuation` 虚拟路径。 |
| `source_refs` | 非空来源证据 ID 数组；事实分类时，每项须指向有效 `source_snapshot` 原文及可复现引文。 |
| `method` | 取值、单位换算和来源解释方法，不能仅重复文件名。 |
| `uncertainty` | 估算必须说明合理范围或不同推导方法；事实和设计选择可选。 |
| `scenario_values` | 估算必须绑定所有关联情景的真实取值，格式见下文；改变范围需要修改依据并重新比较。 |
| `derivation` | 数值估算的可复算底稿；来源数值、单位、限定算术式和目标参数路径，基准及关联共同情景均须吻合。 |

`baseline_values` 必须覆盖该假设全部 `paths`，值与本轮基准严格一致；显式完整父对象可以覆盖其子路径，几个叶值不能代表未完整绑定的父对象。不要使用四舍五入的展示值、旧 run 值或研究模型指纹替代规范输入。改了基准就重建依据绑定；续期值来自当前 `base_continuation.params`，不是从另一候选随意取值。事实的 `source_refs` 沿用上述来源快照的原文、哈希、精确引文、定位与日期要求。

估算和设计选择的 `source_refs` 可以引用真实估算底稿或方案提案，不强制伪装成原文事实。事实仍须引用原文快照。`scenario_values` 是以情景 ID 为键的对象，每项包含 `overrides`、`candidate_overrides`、`continuation_overrides` 三个对象；后两项直接以候选 ID 映射实际覆盖参数，不含说明字段。没有派生或续期覆盖时填 `{}`。例如 `{"low": {"overrides": {"vol_growth_rate": 0.01}, "candidate_overrides": {}, "continuation_overrides": {}}}`。其取值必须与该估算关联的全部 `research.scenarios` 严格一致；删减情景或任意缩小波动幅度会使依据失配。新来源或新的估算解释允许修改，但须更新依据并重新比较。CLI 核验绑定和完整行使，不认证来源解释或估算方法的专业正确性。

`material` 保留为研究者的优先级标记，不再豁免研究。所有已登记估算均须行使应用到全部候选的有效情景；可以在同一情景中检验有关联的多个估算，不要求逐字段单开任务。设计选择均须通过实际候选或情景比较；只有用户明确固定且合同绑定路径和值时，才可以 `user_bound: true` 免除变体。不得通过删掉整条假设逃避检查：完整决策另有基于模型的关键输入覆盖检查。

### 候选及组合的取值依据

完整成本研究还检查候选相对基准的实际参数变化。用 `research.candidate_bases` 将候选和组合关联到已有 `parameter_basis`，例如：

```yaml
candidate_bases:
  - id: shared-operating-estimate
    candidate_ids: [operations, operations-and-tax]
    evidence_refs: [basis-operating-cost]
```

这里引用的依据仍使用原有格式；其 `baseline_values` 指所列候选在基准情景下的实际值。未改变的参数继承基准依据，无须逐候选重新抄写。同一组数值底稿可用于多个同值候选；组合产生了不同的成本或范围时，应登记对应底稿。依据值过期、未绑定的候选变化或情景覆盖与依据不一致，使 `candidate_basis_review` 未通过，计算结果仍保留供研究。

`design_choice` 可以是有明确取值和理由的条件提案，不要求先取得正式报价或审批；不能把实际费用估算改成设计选择以绕过推导。`estimate` 继续保留来源、方法、不确定性、情景取值和数值推导。变化涉及续期时，绑定其 `continuation.*` 参数。已经由 `pricing_rules` 重验的派生收费不要求再造一套求解底稿。

候选输入改变后，更新真实依据并重新比较，而不是只修改输入、沿用旧证据。最终选定和独立校验再次检查这些绑定。它证明所研究的值与所登记的依据对应，不认证单位解释、工程可行性、政策适用或提案已获批准。

### 可复算的数值估算

完整成本决策的数值估算必须提供 `parameter_basis.derivation`。`inputs` 是有来源定位的变量；每项包含 `value`、`unit`、`evidence_ref`、`source_path`。来源须在本依据的 `source_refs` 中且已取得；`source_path` 定位该证据记录的 `value` 内数值或数值数组。文字来源另给原文 `quote`，必须在该位置精确出现，其数值与变量一致。`5.65万`以数值5.65登记，单位换算明确写入公式，不默改为65000。

`outputs` 按点路径覆盖 `baseline_values` 中全部数值叶子；每项包含 `formula`、`unit`，可选 `digits`（0至10位舍入）。公式仅允许登记变量、常数、`+ - * / **` 和 `min/max/ceil/floor`，必须实际引用来源变量；不执行Python脚本、任意函数或外部文件。纯参数赋值可用一个来源变量直接作为公式，不能直接把目标数写成无来源常数式。

例如以下为单个金额路径的底稿片段，实际项目还需分类登记其他关联参数：

```yaml
baseline_values:
  opex_items.0.base_wan: 360
derivation:
  inputs:
    staff:
      value: 30
      unit: 人
      evidence_ref: staff-workpaper
      source_path: value.staff
    wage:
      value: 12
      unit: 万元/人年
      evidence_ref: wage-workpaper
      source_path: value.tested_wages
      scenario_values: {wage_high: 15}
  outputs:
    opex_items.0.base_wan:
      formula: staff * wage
      unit: 万元/年
      digits: 2
```

例中来源应实际登记人数30、研究工资数组`[12,15]`；高工资共同情景的金额必须为450。每个输入的可选 `scenario_values` 按已关联情景替换该变量，未替换者保持基准。同一公式复算基准及所有关联共同情景，不能只更新目标金额而沿用过期的推导来源。已有 `parameter_basis.scenario_values` 仍绑定完整情景，二者分别核对实际研究范围和估算算术。

`research_review.estimate_derivation_review` 保留逐项公式、计算值、实际输入值及差异。其通过只代表数值定位和计算链成立；不证明所选引文真实、单位解释正确、估算方法适合项目或范围充分。不同合理方法需要各自有据的底稿和比较，不能为一致性硬取同一个中值。对可研预测、经验泥产率、寿命等研究估计，应保留这一性质；不得改称事实规避核对。

### 模型自动产生的研究清单

完整合法输入的 `intake` 输出 `research_plan`，列出需分类绑定的关键输入与本项目触发的具体研究事项。完整降本比较的 `research_review.plan_review` 同时检查基准、候选和续期中新出现的事项。先读清单再组织研究，不让业务人员自行列财务字段。

`basis_paths` 中的输入须被假设的 `paths` 覆盖并绑定当前值，或在来源范围复核中逐叶确认属于用户固定参数。已有完整父对象可分类覆盖子项，但几项固定叶子不能豁免整个父对象。日期、范围、估算和设计提案按实际性质登记，不能为了省事把混合对象全部称为事实。

具体研究事项包括投资与更新分别处置、每项运营成本、适用的增值税与所得税事项、资本结构及付款安排。一个领域做过一项试算不代表该领域全部事项完成。`evaluated` 的方向须对该事项相关路径产生真实参数变化；不能只改旁边另一项成本。新增对象或数组项按实际变化的子路径计入，不能用一个父路径变化声称邻近机制也已研究。

资金研究分开检查 `capital-share`（资本金与债务比例及出资负担）和 `financing`（借款来源、期限、利率及偿还条款）。只改变贷款利率、期限或补助，不代表已经研究资本金占比；只提高出资也不代替借款条款研究。用户设定最低资本金比例不是固定该比例。应计算有依据的另一种出资安排，披露初始投入、收益和资金来源条件，或用真实来源约束该选择；不要求穷举所有比例，更不能为了闭合资金假定股东同意追加出资。合成报价任务确实固定这些条件时可明确排除，不能把这种测试范围套到真实项目。

所得税目前分为两项最低研究事项：`income-tax` 对应税率、所得减免及起算安排；`income-tax-equipment-credit` 对应 `income_tax.equipment_credit` 专用设备投资抵免。存在正额固定资产购置或更新时，即使 `income_tax: {}`，也会触发抵免适用性筛查；只有土地等无形资产或流动资金不触发这项资产筛查。已配置抵免时也须处置。触发不表示目录、设备、购置使用主体或资金来源合格，更不预设一定有节省。所得减免反事实不能代替设备抵免研究；真实抵免反事实即使当前税额为零仍可计入研究，但来源、资格和实施条件继续走原有核验流程。

固定或不适用事项可以沿用有原文和明确范围的 `excluded` / `not_applicable`。`paths` 须明确列出具体事项的参数路径或其子路径，例如 `[income_tax.equipment_credit]`；空 `paths` 或宽泛的 `[income_tax]` 不能关闭该抵免事项。同一来源确实支持多个事项时，可以逐一列出其路径。计划已经触发但尚未配置的机制可以直接使用计划给出的路径登记，无需给基准添加虚假的金额或资格。引用核验仍不认证排除理由的语义正确性。分发的三阶段示例明确将抵免变体排除在合成报价任务之外，这不是对真实项目适用性的判断。

该清单按输入的经济内容生成最低研究要求，不是封闭杠杆库。外部新政策、工程替代、共享运营等继续作为新方向进入现有研究和组合流程。清单处置与来源解释、工程适用性均要检查；字段齐全不证明所有外部机会已经发现。

不确定性可能来自数值也可能来自方法。一个估算方法上下小幅浮动，不能代替对另一种合理来源解释或推导方法的比较。情景数量应服务于这些真实问题。

### 共同情景及工程派生

`scenarios[]` 每条包含 `id`、非空 `assumption_ids`、`basis`、非空 `evidence_refs` 和 `overrides`；最多十二项，`baseline` 为保留 ID。`overrides` 可以为空，但须由共同覆盖、工程派生或续期覆盖产生真实参数变化，不能全为空对象充数。情景与假设通过 `assumption_ids`、`scenario_ids` 双向引用。

`overrides` 采用现有参数覆盖结构，在各候选参数之后应用。对象字段递归合并；候选、共同情景及派生覆盖中的数组字段（如 `opex_items`）须提供完整数组并整体替换，不支持数字键稀疏覆盖。同一情景代表对全部候选相同的外部条件或估算解释，不能让某候选偷偷恢复自己的有利取值。情景只能改变所关联假设的路径，不能修改决策合同固定参数。需要变更固定边界时，返回第一阶段修改合同并重新比较。

绑定 `cost_goal` 后，共同估值率是决策的固定尺，研究情景不得通过改变 `discount_rate` 帮助某方案取得优势。融资利率可以作为有依据的条件变化；它与比较折现率不是同一个参数。确需比较另一个估值立场时，另修订合同并重新计算整组结果。

工程关系需要按方案重新推导时，可以添加 `candidate_overrides`：键是候选 ID，值包含 `overrides` 与说明工程推导的 `basis`。派生变化仍须在关联假设路径内，不得改写共同冲击的同一变化路径，也不能夹带新措施。费用与数量、设备配置、时序等相互关联时，应实际重算关联字段；CLI 校验路径与计算，不验证该工程推导是否正确。

情景结果保留每个候选的指标、可行性、约束、口径、模型限制和参数哈希，不能只保存赢家。某条件失效导致方案不可行是有用结果；参数错误或不完整情景无法完成计算，需要修复后才能收口。全体候选都未受实际影响的“情景”不能充当重要估算测试。

### 续期也属于研究对象

不同期限比较的适用视角、同等服务和完整续期要求见[成本契约](COST_PERSPECTIVES.md#同一服务期间的比较)。续期不是一个平均年费字段：它的全部参数作为虚拟路径 `continuation` 加入方向、假设、基准识别及组合差异检查；该路径不属于项目 input schema。基准没有续期时其值为 `null`，登记新增整份续期用 `paths: [continuation]`，并说明其完整安排；存在续期时可使用具体的 `continuation.<参数路径>`。不得通过宽路径隐去未说明的成本、资格或交接变化。

每个共同情景的可选 `continuation_overrides` 在存在续期时须完整列出**全部带续期的候选 ID，以及有 `base_continuation` 时的 `base`**，即使自动基准不在候选列表中。每个值为 `{overrides, basis, evidence_refs}`，这里的 `overrides` 才是对该完整续期参数的覆盖；数组仍整体替换。无变化也显式写 `{}`、给出原因和真实依据。不能把 `continuation` 放进普通情景 `overrides`，也不能仅覆盖赢家而让其他续期静默固定。

续期变化须在所关联假设的 `continuation` 路径内，继承共同折现尺、服务与财务门槛。除逐情景完整说明外，续期服务安排须有实际参数变化的有效条件测试，不能每轮都写空覆盖。重要假设仍须行使全部候选：例如同一长期运营估算，短方案的续期费用和长方案尚未到期的费用都应按同一解释重新推导，不能只改变有续期模型的那一组。

比较同时保存 `decision_params_sha256` 与 `base_decision_params_sha256`，覆盖原合同和续期参数；各情景保留完整共同期成本及续期约束结果。续期原文、估算底稿和情景覆盖均须绑定实际 supporting 记录。一个哈希完整的续期模型仍可能包含错误估算或不成立的交接假设；CLI 不认证这些语义。

### 组合与收口

#### 按相同资金规则反求收费

措施参数与计算得到的收费需要分开核验。例如设备更新安排单独比较时需要提高收费，组合节能措施后，按同一资金底线重新求出的收费可能回到基准值；这不表示更新安排被撤销。仅写“已重定价”也不能证明这一点。

使用可选 `research.pricing_rules` 登记可重验的定价规则。每条包含 `id`、`variable`、`target: cum_cash_min`、非负 `target_value`、有限求解边界 `lo/hi`、向上取整的 `rounding_digits`、`candidate_ids`、`scenario_ids`、`excluded_scenarios`、`basis` 和非空 `evidence_refs`。当前只支持既有求解器的综合含税水价 `tariff_blended_gross` 或年度容量费 `capacity_fee_wan_per_year`，不包括续期收费或其他目标。

`candidate_ids` 必须包含真实基准候选，以及需要按该规则重验的单项和组合；同一候选的同一收费不能登记重叠规则。基准情景始终参与；每个已登记共同情景必须明确纳入定价或在 `excluded_scenarios` 中按情景ID写出排除理由。不纳入定价不等于删除该研究情景、确认风险可接受或豁免可行性检查。研究审查仍保留其实际结果、资金缺口和排序变化。规则依据应说明为什么采用这组保障条件，不能为降低价格默默略去不利情景。

CLI 对候选在各纳入情景的真实模型分别调用已有 `solve`，取所需收费最大值，再向上取整；核对实际候选及情景中的收费并重算资金底线。`research_review.pricing_rule_review` 披露已保障和未保障情景、求解结果及输入核对。只有基准、单项措施、组合结果均由同一规则成功重验，该规则对应的收费路径才可在组合中回到基准；投资、维修、更新等其他独立变化仍须保留。缺少规则、错价、漏列情景、无解或规则不一致均不取得这一例外，规则失败阻止研究收口。

这项核验不自动创建候选、不改变输入、不证明定价是商务最优，也不替代投资回报、审批和合同约束；它只复现已经声明的累计资金定价方法。收费条件变化后，须重算全部受影响候选及研究情景，再重新比较和确认。

`combinations[]` 每条包含至少两个 `candidate_ids`、`result_candidate_id`、`basis` 与非空 `evidence_refs`。可以组合时，`result_candidate_id` 指向另一条已完整计算的候选；数值较差也要保留这个实际结果。只有来源支持的结构不兼容才使用 `null`，并给出完整 `exclusion` 和来源快照。登记本身不证明完整组合的参数构造正确，Agent 仍须检查相互作用。不得把独立节约额相加作为组合结果，也不得以某单项表现差宣称其全部组合不会更好。

组合替代原措施时，使用可选 `replaced_candidate_ids` 显式列出被替代的单项候选 ID。例如已有工程措施加银行贷款，再改用专项债，组合成员可以引用旧完整方案和专项债候选，但必须移除旧银行贷款单项。CLI 递归展开有效措施，拒绝循环谱系、同一结果相互矛盾的定义，以及仍包含已声明互斥措施的组合。替代项只能来自该组合继承的单项，不能随意删除无关候选。

CLI 自动检查所有已测情景赢家与剩余已研究单项的组合处置，输出 `combination_coverage`：已包含（`already_included`）、已有实际组合（`tested_combination`）、有依据排除（`excluded`）或尚未处理（`missing`）。缺失项会阻止进入选择，不能用“已有很多组合”或一句停止理由绕过。实际组合须具有准确的有效措施集合且改变参数；附带另一项措施的超集不能代替这项组合，换 ID 复制原参数也不能充数。已声明单项互斥可继承到包含它的完整方案，已被替代掉的措施不参与继承。选择非赢家时，`finalize` 对该候选执行同样检查。

这项检查只针对当前已有措施与优选候选，不枚举全部子集，也不声称发现了所有外部政策。CLI 验证声明的组合谱系、引用、排除来源快照和实际计算，不能验证工程合并或排除理由的事实真伪。新组合改变赢家后，需要继续处置新赢家剩余的措施；未落实的真实实施条件仍保留为条件，不能为收口伪造互斥。

只有在全部已测情景均没有参数差异时，原基准才不作为新增措施。某措施或组合只在不利情景生效，也要保留并接受组合覆盖检查。省略自动基准、另建可按情景重新推导的基准候选时，可设置 `research.baseline_candidate_id`；该候选在基准情景的完整参数必须与比较基准一致，CLI会以它各情景的参数识别基准，不按名称猜测。

推荐前结合材料自查，反查最影响取舍的排除：完整条款中的允许部分或例外是否改变适用范围，完整反事实计算是否支持数值理由。一个税种、余额或会计科目为零，并不证明完整经济影响为零；关联税费、资产基数、融资和支付安排发生变化时须一并重算，不能只看单个字段。结论范围不得超过所读原文和实测范围。

`stopping_reason` 解释为什么当前研究足以支持建议、尚未覆盖的边界和重新研究的触发条件。数值全绿、菜单已经生成、候选数量够多或用户已选一项，都不是研究完成的理由。记录很少也可以充分；记录很多仍可能遗漏一个决定性的事实或方案。

## `research_review` 输出与使用

比较文件中的 `research_review` 提供 `status`、`ready_for_selection`、`issues`、`scenario_results`、`baseline_winners`、`robust_winners`、`recommended_candidates`、`assumption_tests`、`combination_coverage`、`source_exclusion_review`、`plan_review`、目标与研究哈希。各情景的 `winners` 可以包含多个并列候选；`robust_winners` 为所有已测情景赢家集合的交集。

| 状态 | 含义及后续动作 |
|---|---|
| `not_assessed` | 没有研究登记，只有数值比较；继续研究。 |
| `incomplete` | 已登记研究仍有未处置方向、未解释变化、未行使的重要假设或其他问题；按 `issues` 继续修正。 |
| `no_feasible_candidate` | 研究检查完成，但基准条件下没有可选的非基准候选；分析控制约束，继续提出措施或有依据的边界调整。 |
| `stable_within_tested_scenarios` | 存在在所有已测情景中均位列赢家集合的方案；仅表示该有限范围内的稳定性，可能仍并列或有待落实条件。 |
| `conditional_on_assumptions` | 不存在覆盖全部已测情景的共同赢家；需要交付各条件下的选择及其理由，不能宣称稳健唯一最优。 |

`source_exclusion_review` 逐条输出作用范围、证据引用与问题，状态为 `source_reproduced` 或 `unsupported`。前者仅表示来源登记、正文哈希和引文能复现，不表示排除理由已获专业认证。未绑定 `--evidence`、证据缺失或重复、正文/引文不匹配、候选范围未覆盖都会阻止该排除收口。

`recommended_candidates` 是供审查的计算候选集合，不是自动替用户决策。即使 review 为稳定，真实来源误读、遗漏重大假设或错误工程估算仍应使 Agent 返回研究。若只有原基准稳定，说明新措施没有在已测范围内证明更好；若要选择维持原方案，也须作为明确可选候选记录，不能暗选一个试算。

候选原有的 `numerically_feasible`、`eligible_for_selection`、`eligible_for_research_selection` 及两个 shortlist 继续表达各自的数值、口径、模型和实施条件门禁。它们不包含完整的研究收口判断。`finalize` 同时要求 `decision_review.passed`、选中候选满足对应选择范围门槛和 `research_review.ready_for_selection`，不能把旧的 `best_by_objective` 单点排序当作推荐证明。

`decision_review` 核对成本目标与三类要求的真实引用，并列出候选条件、续期依据及付款方收支引用审查。条件声明为 `satisfied` 或 `not_applicable` 时不能引用不存在、重复或仅在 unresolved 的证据；付款方收支与续期也不能只填一个虚构编号。共同情景按重算后的实际付款方收支引用再次检查，不能在情景新增无依据收入绕过基准核验。坏引用的候选失去选择资格；若原推荐依赖该候选，或共同情景收支引用未通过，推荐收口会被撤回。普通估算登记为 `unverified` 和未落实条件为 `pending` 是诚实的条件研究，不等于缺失的 ID 可以通过。CLI 只确认记录可解析，不认证引用内容足以证明结论。

## 选择与成果如何保留结论边界

`compare` 同时生成 `decision-brief.json` 和 `decision-brief.md`，直接承接已经计算并绑定的主次目标、数值首组、研究建议、并列和条件分支，不另行排序。研究或决策核验未通过时摘要明确为探索，不能把保留的数值首组称为正式推荐。向用户说明建议应以这份产物为数值底稿；如要优先考虑另一个目标，明确变更决策合同并重算，或解释用户选择的不同取舍。

`finalize` 在选定运行根目录生成同名摘要，区分计算建议与用户实际选择；成本名义额、现值、共同服务期与原合同、增值税发生额与期末留抵分别标注。摘要引用比较、选择和完整计算结果哈希，并纳入 `final-run.json`；`verify-final-run` 重建核对，不允许改摘要来改写排序或混用另一运行数字。它是可直接引用的确定性底稿，不是对任意自由文字报告的语义认证。

向用户说明推荐理由、采用与不采用的影响、重要条件失效的结果以及会翻转排序的假设。不要让用户靠查看原始 JSON 才发现这些限制。可以选择条件方案，也可以基于明确取舍选择非共同赢家；选择记录保留 `decision_reason` 和 `acknowledged_research_status`，说明所作的决定，不能抹去翻转或将自选包装成稳健最优。

选择仍绑定具体比较、完整参数、决策合同、证据及软件身份；第三阶段重新核验研究并全量计算。`selection_scope=conditional_research` 允许保留待落实实施条件，不允许跳过不完整研究。选定后的 Word、图表和一页说明继承同一研究边界。新证据影响选择时返回研究并生成新比较，旧判断作为历史保留。

有续期的最终运行同时交付原合同和续期完整成果、共同期间 `cost-comparison.json` 及 `cost-cashflows.csv`，经 `verify-final-run` 绑定核验。回报要求、实际现金门槛和成本来源不能在续期中丢失；共同期间成本最小也不代替两个合同各自财务可行性。说明基准是原材料测算还是本次估算构成的条件基准，不能把相对后者的降幅直接称作原材料总成本下降。

## 验收边界

机械验收检查共同情景确实重算、数值不采用有完整反事实候选、结构排除有可复现的来源引文、排序翻转与并列如实显示、无解释改参被拦截，以及不完整研究不能定稿。业务验收检查来源语义是否正确、方向和场景是否抓住重要问题、依据是否适用、建议是否值得采用。这两层都需要成立；“字段齐全”不能代替“一轮正常使用即可获得充分研究的建议”。

### 共同条件与组合参数核验

共同情景的实际参数变化也计入相应研究方向，例如全部方案在共同低水量下重算，属于需求研究，不要求另外造一个“降低水量以节约成本”的候选。

情景必须覆盖全部参与比较的方案，但不要求每个方案数值都改变。某项折扣未取得时，原本没有折扣的基准可以保持不变；须通过共同或逐候选覆盖显式应用同一条件，至少有一个方案受到实际参数变化，并且全部方案均完成重算。省略某方案或只改说明文字不能满足这一要求。

`combination_retention_review` 检查组合声称继承的独立参数变化是否在全部已测状态中丢失。例如分别调整三个经营成本分项，合并完整数组时把第一项恢复成基准，不能仅凭组合成员 ID 宣称已包含三项措施。检查保留有依据的条件交互：措施可以只在某一已测情景中生效，也可以显式替代旧措施。多个措施共同改变同一字段时，产品不凭路径推断工程兼容性或证明叠加幅度；这些仍须完整计算及依据核验。

直接用于续期、付款方、条件等模型字段的外部依据也必须保存为原件快照，不能将报价改写为普通字符串而免去绑定。没有正式报价仍可以研究估算：该字段应引用已在 `research.assumptions` 登记的 `estimate` / `design_choice` 的 `parameter_basis`，沿用取值、来源与推导审查；散装估算文字或未登记的同名对象不能代替它。用户同一条消息可以固定多个参数，模型引用按相关参数与实际合同锁核对，外部用途不能借此变成对话豁免。格式读写位于成果适配层，领域契约仅保存原件标识与定位描述；提取器的支持范围及定位有效性由原件重放检查落实。
