# 三阶段产品契约

产品帮助业务人员把初始项目资料转化为有依据的候选方案，并将用户选定方案生成完整、可复核的计算成果。LLM 与 skill 负责理解材料、发现措施和组织判断；CLI 负责确定性计算、约束检查、比较及成果绑定；用户作最终选择。

## 第一阶段：建立起点与探索范围

交付来源基准、参数与证据、冲突/估算清单，以及独立的 `decision-contract.yaml`。合同规定成本目标的主体、单位、收支范围、比较期间、折现口径、硬约束、固定参数和实施条件。原始资料中的拟定值不自动成为不可改变的事实。

资料不足时可开展用户已授权的有依据估算和条件情景。记录估算方法、适用范围和待替换依据；缺失事实不得伪造。计算不可表达的机制单独登记。不要为了启动试算要求用户先提供完整财务工作簿。

目标口径需单独核对。当前 `total_lifecycle_net_cost_wan` 是引擎既有投资、经营、财税与终值汇总口径，不能直接标作政府净支出；含税单价也只在补助、量、期限等边界固定时可作付费比较代理。本版没有新增政府净负担核算、任意多变量优化或自动政策适用性判断。目标不可由现有指标表达时，应另建可复核收支底稿并披露限制，不能改名替代。

## 第二阶段：措施、组合与选择

每项措施连接：有效依据 → 本项目适用条件 → 实际行动 → 关联参数变化 → 成本、责任及实施条件。参数敏感性只证明影响，不证明措施可实现。

比较始终加载第一阶段的决策合同；候选不能删除合同中的硬约束或修改固定参数。改变合同意味着重新登记目标/边界并重新比较。试算成功、数值约束通过、实施条件已登记满足和用户确认分别记录。条件情景可以比较，但不自动成为可定稿方案。

单项措施的收益不可相加冒充组合结果。完整组合逐一重算，以相同服务边界和评价口径比较。LLM 可以给出有条件、限定候选范围的推荐，CLI 的机械排序不构成用户选择或全局最优证明。

没有满足要求的方案时，解释控制性约束并继续研究措施、补充证据或提出边界变更。不能仅因生成菜单、反求收敛或用户偏好而宣告方案可行。审批、资质和工程可实施性由相应责任方核实，CLI 仅检查声明与记录完整性。

## 第三阶段：确认、完整重算与交付

用户选择绑定具体比较哈希、候选 ID 和完整参数哈希。`finalize` 验证决策合同、证据和软件身份，重新比较选中候选并调用既有完整成果构建链。最终包记录选择依据、来源参数、决策合同、软件身份和全部成果哈希；任何变化都需要重新比较/确认，旧成果不可覆盖。

正式选定成果只使用已确认的最终运行。最新试算、最高编号或指标最优的运行不自动成为最终运行。独立单次测算仍允许生成基准或条件成果，必须明确用途，不假冒选定方案。

完整计算成果包括适用的投资融资、收入成本税务、财务报表、项目及资本金现金流、偿债与资金平衡、敏感性和确定性分析；不适用与未决项保留说明。Word 和图表按请求从同一最终运行组织，不能在排版阶段重算或更改参数。

## 产品验收

- 通用合成项目验证完整的建模、候选比较、用户选择、最终重算及结果绑定。
- 有收益但资金不闭合的候选不能进入选定成果；未决实施条件不可由数值绿灯掩盖。
- 新措施及组合产生真实重算；目标/固定参数/证据/选择被改变时能被发现。
- 真实项目留在案例仓；从案例提炼的缺陷用通用反例覆盖，禁止项目常量或专用结论进入内核。
- 单元测试、真实案例复算、业务可用性、用户确认和发布安装分别验收。
