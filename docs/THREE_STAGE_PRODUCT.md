# 三阶段产品契约

产品帮助业务人员在一段连续交互中，从初始项目资料得到经过主动研究、有依据的建议，再将用户选定方案生成完整、可复核的计算成果。业务人员提供资料、目标与反馈，不应承担发现模型错读、提醒遗漏方向或重开任务比较答案的责任。Agent 在同一案例内反复研究、测算和复核，内部多次计算属于正常使用。

LLM 与 skill 负责理解材料、寻找依据、设计方案和组织判断；CLI 负责确定性计算、研究记录的机械检查、可比性与情景比较及成果绑定；用户作最终取舍。产品追求已知约束和可取得依据下充分研究后的合理推荐，不承诺任何资料条件下的全域绝对最优。同一事实、边界与目标应得出可复核的比较；存在实质不确定性时应交付条件分支，而不是随机挑一组假设输出唯一“最佳”。

三阶段允许往返；各阶段输入输出、当前产物和历史记录见[案例工作流](CASE_WORKFLOW.md)。

## 产品职责与演进原则

产品是供 Agent 使用的专业财务计算与决策工作区。持续价值在于经过验证的领域模型、完整组合与情景重算、可复核底稿、当前成果与历史判断、可信交付。检验一个功能是否值得做，应问：优秀咨询专家使用时，它是否仍能减少劳动或提高可验证性。模型能力提高应扩大可研究的方法和措施，而不是要求所有模型遵循同一条预设思考路线。

原文理解、估算方法选择、政策适用及研究充分性属于专业判断，CLI 不声称认证。Skill 提供方法和工具入口，避免为某次误读不断增加通用禁令。领域算术、资金闭合、同等服务可比性、实际输入与依据一致性、当前成果绑定则由代码检查；这些责任不因模型更聪明而消失。

同事实、同方法、同目标与比较规则应得到相同计算和排序。同一资料允许提出新的有依据方法，须披露方法差异并计算其对建议的影响。推荐规则本身也须有合理依据；结果展示严格主目标首组、已登记规则首组及成本差额，帮助判断容差和次目标的取舍，不擅自为用户改规则。

减少重复登记：计算层已知的收费边界可直接生成草案，无须 Agent 重写求解循环；候选依据只绑定它实际使用的共同及专属情景；纯展示字段不要求虚构财务变体。原输入、依据和用户决策仍完整保留。登记齐全或门禁通过只证明已记录计算的特定性质，不证明外部机会已全部研究。缺失依据限制相应结论，不能阻止有用探索，也不能把真实资金缺口变成可行。

## 第一阶段：建立起点与探索范围

交付来源基准或有依据的条件起点、参数与证据、冲突/估算清单，以及独立的 `decision-contract.yaml`。合同的 `cost_goal` 把实际目标及依据绑定到成本视角、名义/现值、共同服务期间、折现率和三类要求：服务、合规、投资回报。服务与合规须引用已登记实施条件；回报适用时关联真实收益率或 NPV 下限，不适用则给出理由与依据。合同仍记录硬约束、固定参数及责任方，不能把待落实条件写成已满足，或把别的模式的回报要求照搬进来。多个目标须明确主次；次级目标不能在比较后偷偷替换主目标。原始资料中的拟定值不自动成为不可改变的事实。

输入转换须保留原文限定语和推导过程。设计能力、雨季峰值与年均处理量，全系统与项目增量，设备使用年限与项目日历年份，账务金额与现金收付均不能直接互换。原文没有建立所需含义时，缺失事实保持未决，工作估算另行标明方法、适用范围和可能改变结论的替代解释。

研究中的来源事实须以 `parameter_basis` 绑定当前已解析基准值、分类、取值方法及 `source_snapshot` 原文；不能把估算标签改成事实就免除研究。资料内的未来预测仍按估算处理。绑定规则覆盖续期输入，但机械匹配不认证来源解释、真假或重要性判断，详见[研究约束](RESEARCH_REVIEW.md)。

资料不足时可开展用户已授权的有依据估算和条件情景。记录估算方法、适用范围和待替换依据；缺失事实不得伪造。计算不可表达的机制单独登记。不要为了启动试算要求用户先提供完整财务工作簿。

目标口径需单独核对。[成本口径契约](COST_PERSPECTIVES.md)分别提供投资经营支出、项目资金净支出、服务费与补助合计，以及指定主体声明范围内净支出。用户要降低建设运营总成本时，应说明适合的项目成本视角，如包含财税融资与流动资金的 `project_cash_cost_net`，不能自动偷换为本级财政支出或较窄的投资经营费用。收支范围不完整时不输出完整净额；金额可算不代表条件成立。主目标统一使用 `decision_cost_wan` 或 `decision_cost_npv_wan` 最小化、单位万元，由 `cost_goal` 决定机器范围；历史成本和单价指标保留作探索，不能改名替代。目标不可表达时披露限制，不假称完成 CLI 比较。

## 第二阶段：措施、组合与选择

每项措施连接：有效依据 → 本项目适用条件 → 实际行动 → 关联参数变化 → 成本、责任及实施条件。参数敏感性只证明影响，不证明措施可实现。Agent 主动审查服务需求、建设更新、运营、税收支持、融资支付、实施合同六个通用方向；有依据排除不适用方向，不要求每方向都造一个候选。研究范围随着资料和新依据扩展，措施清单不封闭。

比较始终加载第一阶段的决策合同；候选不能删除合同中的硬约束或修改固定参数。改变合同意味着重新登记目标/边界并重新比较。试算成功、数值约束通过、实施条件已登记满足和用户确认分别记录。条件情景可以比较，但不自动成为可定稿方案。

`cost_goal` 下保留累计资金非负、完整模型和合同显式数值约束，不把现金 DSCR≥1作为全部债务的自动硬门槛，也不对续期普遍施加账面 DSCR≥1。当期经营现金不足但累计资金闭合、显式约束通过时，转为带偿债资金可用性条件的研究；实施时须核实结余实际可用、受限用途、分配及融资条款，不能写“不适用”豁免。真实累计缺口不能靠另写财政计划、登记条件或用户偏好消除。CLI 不证明银行批准，也未模拟独立偿债储备账户。目标、要求分类及已满足/不适用条件的证据引用另由 `decision_review` 核对；未绑定、不存在或重复的依据不能支撑推荐。

补助筹资用途及影响偿债评价的运营投资分类按[资金结构契约](FUNDING_STRUCTURE.md)核对。`model_limits` 非空时，即使数值通过且实施条件已登记满足，也不能生成选定成果。保留旧数值便于复算，不代表已形成完整资金方案。

单项措施的收益不可相加冒充组合结果。完整组合逐一重算，以相同服务边界和评价口径比较。数值不利或收益较小属于已测后不采用，仍保留完整反事实候选及共同情景；不能写成结构不兼容而省掉组合计算。一个税种、余额或会计科目为零不代表完整经济影响为零，关联税费、资产基数、现金和支付安排须同步重算。重要估算和未固定设计选择须在候选或共同情景中行使；共同情景应用到全部候选，工程派生量发生变化时按注明的方法同步重算。影响目标、可行性或最终取舍的融资支付变化，不能因为“不改变资源成本”而不研究。

期限方案须在相同开工、投运时点和共同服务终点比较，并逐段保持处理量一致。目前只有指定付款方净支出视角支持不同原合同期限；短合同及短基准须提供完整 `continuation` / `base_continuation`，保留原合同全部期末责任，再单独计算到共同终点的续期服务。不能截长、补零或按平均年费外推；也不能为获得可比结果改变业务目标。每个共同情景明确覆盖所有续期模型，续期自身须有有效条件测试；折现尺保持固定。具体接口见[成本口径](COST_PERSPECTIVES.md)和[研究约束](RESEARCH_REVIEW.md)。

方案集的 `research` 与比较结果的 `research_review` 将方向、假设、情景、组合与收口理由绑定到本轮实际计算。未登记或研究不完整时可以继续试算，不能进入选定成果；研究通过也不能替代成本目标审查、数值可行和条件引用核验。排序翻转时可完成研究并提出条件建议，但不能声称有稳健赢家；用户可以明确作条件取舍。详见[研究与推荐约束](RESEARCH_REVIEW.md)。

每个原合同、续期及共同情景均生成 `model_eligibility`，共用检查结果和政策发现。内部计算错误、已知 `scope_gap` 或未支持模型不能作为完整降本比较；明确政策“不满足”的设置保留对照计算，但退出优选、研究推荐和选定成果。政策“证据不足”生成具体的 `policy:<scope>:<key>` 待落实条件，仍可作条件研究；模型尚未取得对应依据时，通用条件确认或手工把该自动条件改为满足均不能提升实施资格。补入有依据的费用估算，或补齐相应模型资格证据后重新计算，可恢复资格。普通告警不一律阻断。

有效研究差异取决于计算输入，不能只改名称、来源或展示元数据冒充措施、情景和组合。实际财务参数发生变化，即便本次输出恰为零，也应保留这个真实测试。来源与标识更正仍遵守完整输入的历史和绑定纪律，不等于发现新的经济措施。

推荐前结合材料自查，对最影响取舍的排除做一次反证审查：完整条款是否保留允许部分和例外，完整反事实计算是否支持排除范围。来源或实测只支持局部结论时，不得扩大为整类禁止或全部方案无收益。来源绑定和计算引用可由 CLI 校验，语义真实性与专业判断仍由 Agent 负责。

第二阶段的交付物须回答：为什么推荐、哪些替代方案未被采用、哪些条件会改变选择、关键条件失败后怎么办。最低单点数值、通过校验、生成菜单或达到预设试算次数均不是收口理由。LLM 可以给出有条件、限定候选与情景范围的推荐，CLI 的机械排序不构成用户选择或全局最优证明。

没有满足要求的方案时，解释控制性约束并继续研究措施、补充证据或提出边界变更。不能仅因生成菜单、反求收敛或用户偏好而宣告方案可行。审批、资质和工程可实施性由相应责任方核实，CLI 仅检查声明与记录完整性。

## 第三阶段：确认、完整重算与交付

用户选择绑定具体比较哈希、候选 ID 和完整参数哈希，并保留选择理由和对研究状态的确认。新 `finalize` 必须有完整、证据绑定通过的 `cost_goal`，同时验证决策合同、数值与条件、软件身份和研究门禁，重新比较并调用完整成果构建链。最终包记录选择依据、来源参数、决策合同、软件身份和全部成果哈希；任何变化都需要重新比较/确认，旧成果不可覆盖。用户确认不能替代缺失的研究、坏引用或资金缺口，报告完成不能提升原有推荐的证据等级。

正式选定成果只使用已确认的最终运行。最新试算、最高编号或指标最优的运行不自动成为最终运行。独立单次测算仍允许生成基准或条件成果，必须明确用途，不假冒选定方案。

最终重算复核原合同及续期的 `model_eligibility`，与比较时的资格及用户选择范围一致后才写出完整成果；资格结果进入最终哈希绑定。`verify-final-run` 对旧成果仍作历史完整性与绑定核验，不能把旧版通过结果解释为已按新版规则重新验收。当前选择须重新比较，不能直接沿用旧软件版本的推荐。

完整计算成果包括适用的投资融资、收入成本税务、财务报表、项目及资本金现金流、偿债与资金平衡、敏感性和确定性分析；不适用与未决项保留说明。Word 和图表按请求从同一最终运行组织，不能在排版阶段重算或更改参数。定稿后的说明、导出脚本和临时展示文件放在 `exports/run-NNNN/`；`input/` 整棵目录属于当前性绑定，不能把纯展示文件写进去而使已选成果过期。真实依据或选择变化才返回研究，文件误放的恢复规则见[案例工作流](CASE_WORKFLOW.md)。

存在续期时，同一最终运行包含原合同 `deliverable/`、续期 `continuation-deliverable/`，以及共同期间 `cost-comparison.json`、`cost-cashflows.csv` 总底账，全部进入最终绑定。报告须分别说明共同期间成本与各合同财务/现金结论，不能只交原合同却宣称已交付共同服务期全套成果。每个主要结论在其出现的位置说明模型对象、比较基准与条件，不能让用户靠外部 README 或聊天解释纠正主报告。基准含代理估算时，降幅也须明确相对该条件基准，不能称为原材料已测总成本的下降。

## 产品验收

- 通用合成项目验证完整的建模、候选比较、用户选择、最终重算及结果绑定。
- 从初始材料出发的正常业务交互，检验 Agent 能否主动识别重要方向、正确理解来源、测算关键假设及组合、给出有理由的推荐；不能由全知主控提示具体缺陷后仍计作一次自主通过。
- 单点赢家随共同假设变化而翻转时，输出翻转条件；并列不强行选优；未完成研究或未解释参数改动不能因用户选择而被放行。
- 有收益但资金不闭合的候选不能进入选定成果；未决实施条件不可由数值绿灯掩盖。
- 新措施及组合产生真实重算；目标/固定参数/证据/选择被改变时能被发现。
- 真实项目留在案例仓；从案例提炼的缺陷用通用反例覆盖，禁止项目常量或专用结论进入内核。
- 单元测试、真实案例复算、业务可用性、用户确认和发布安装分别验收。

两次独立交互不必采用完全相同的方案名称，但差异必须能由来源、用户边界、估算方法或已解释取舍说明。把关键错误留给第二次重跑发现，说明第一次推荐验收未成立。重复已参与开发的案例只提供回归与使用证据，不能证明未见项目的通用成熟度。
