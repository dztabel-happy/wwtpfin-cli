# wwtp-fin ↔ DocxKit ↔ ChartKit 边界

> wwtp-fin 负责“结构化项目材料 → 可核验咨询语义”；DocxKit 负责“语义 → Word”；ChartKit 负责“数据与图表 brief → 图片”。三者只在文件和 agent 层交接，不互相调用。

## 职责边界

| | wwtp-fin | DocxKit | ChartKit |
| --- | --- | --- | --- |
| 负责 | 参数、证据、计算、检查、裁决、完整机器语义、财务核心稿、表格数据、图表 brief | 章节排版、样式、页眉页脚、目录、图表编号、`.docx` | 数据图的图型、轴、图例、样式与图片导出 |
| 输入 | 项目参数与项目证据 | 由 `document.json` 转出的 `report.json`、表格、图片资产 | 图表 brief 与对应 CSV/结构化表 |
| 输出 | `document.json`、`report.md`、`result.json`、tables、figures briefs、质量与告警 | `.docx` | PNG/SVG/PDF 等图片与题注 |

```text
材料 → INTAKE → wwtp-fin build
                 ├─ document.json → report.json → DocxKit → .docx
                 └─ figures/*.json briefs + figures/data/*.csv → ChartKit → 图片
                                                        │
                                      图片路径 + 题注 ──┘
```

`build` 不启动 DocxKit 或 ChartKit。`report.md` 是财务咨询核心，不是完整成篇报告；报告 agent 应读取完整 `document.json`、表图目录和经核验的补充资料后再组织内容。下游不重算财务结果或替换裁决。交接字段、示例命令见 [examples/handoff/README.md](../examples/handoff/README.md)。

`report.md` 只保留影响财务判断的计算结果及其解释。逐期中间序列、模型自检计数和审计底稿不进入咨询核心，仍可在 `result.json`、`document.json` 和技术表中追溯。

## wwtp-fin 不做什么

- 不把材料改写成完整的咨询文笔、工程设计理由、现场调查、方案比选或规范原件；这些是项目材料或下游报告作业。CLI 只呈现已结构化并有出处的事实、计算和裁决语义。
- 不输出 Word、PDF、图片或版式；不包含 Office 提取器、原始文件校验、报告模板和 benchmark 材料。
- 不以行业惯例补齐缺失融资、税务资格、基准收益率、授权或项目事实；应登记 `unresolved`、`required_user_inputs` 或 `declared_basis`。
- 不把 `report.md` 当作完整咨询报告或自由续写草稿；非财务项目事实留在 `document.json` 和证据层，由报告 agent 按资料充分性决定是否成章。
- 不把“模式名称”当作算法开关，不按项目专名、旧表格或案例答案分支。

## 当前能力边界

| 范围 | 当前状态 |
| --- | --- |
| 概率分析 / 蒙特卡洛 | 未实现。 |
| 长期资产混合用途进项税调整 | 支持显式逐年调整序列、税务依据与所得税扣除性；不按收入比例推断。 |
| 建设期利息非资本化 | 支持；利息仍进入总投资与筹资，是否税前扣除必须显式声明。 |
| 运营期新增长期贷款提款 | 支持绑定同年重置或扩建资产的专项长期贷款；不接受无明确用途的运营期提款。 |
| 多方案比较 | 支持最多 30 个使用者明确给出的候选，逐个计算硬约束、指标、参数变化、代价与责任；不自动生成参数或替用户选择。 |
| 决策合同与最终计算 | 比较继承独立合同中的固定边界、目标和约束；用户选择绑定完整参数，`finalize` 重算完整成果并验证引用。条件满足是责任方登记，不是 CLI 自动认证。 |
| VfM | 仅在显式提供 PSC/PPP 所需输入时输出；缺 `vfm_opex_uplift` 或政府投资即不产出，不替代完整法定 VfM 资料与论证。 |
| 地方税 | 房产税、城镇土地使用税、印花税可逐年输入并声明可扣除性；不自动按地方规则推导。 |

计算内核不只服务特许经营项目。O&M、存量转让、新建、改扩建及其已支持组合共享同一套水量、收入、成本、税、融资和财务评价模型；模式字段只描述真实交易与资产边界。没有建设、取得或特许经营安排的项目，不得为了通过校验套用 BOT/TOT 标签，应选择与实际边界相符的模式，或明确登记当前模式不受支持。

投资定额、地方价格信息和工程量清单属于上游估算依据。LLM 应记录地区、版本日期、调整系数、价税口径和来源，在已授权的探索中形成有依据的估算情景；用户选定前不得将估算提升为已核定事实。CLI 不内置定额库，也不把缺失依据替换为经验值。工作流见 [三阶段产品契约](THREE_STAGE_PRODUCT.md)。

完整领域语义以 [DOMAIN_CONTRACT.md](../DOMAIN_CONTRACT.md) 为准；能力矩阵用 `wwtp-fin capability` 实时查看。
