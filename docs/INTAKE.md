# INTAKE：转化 LLM 作业指南

## §28 管线定位

你是“用户材料 → CLI 合法输入”的转化者，不是咨询结论生成器。你的交付是参数文件、项目证据文件和转换日志；产品才是计算、检查与咨询核的产出者。先读取 `schema --kind input`、`schema --kind project-evidence` 与 `examples/minimal_complete/`，再映射材料；契约没有的内容不得伪装成参数。

转换前先建立四张账：来源登记表、来源到字段映射表、冲突台账、完整性矩阵。来源登记表记录文件、日期、版本、权威状态和适用范围；冲突台账逐字段保留所有冲突值及裁决依据；完整性矩阵至少覆盖计算参数以及风险分配、绩效监督、终止补偿、移交四类咨询事实。详细判据见 `skills/wwtpfin-consulting-core/references/conversion-discipline.md`。

## 缺参诊断与用户提问

先把材料中能确定的内容写成参数草稿，再运行：

```bash
wwtp-fin intake -p project-draft.yaml -o intake-advice.json
```

`source_required` 必须回源或询问用户，不给数值建议；`confirm_default` 是产品口径建议，只能在 `suggestion_condition` 成立且用户确认后写入。按“阻断计算的项目事实 → 影响裁决的依据 → 可确认的产品口径”一次性分组提问，避免逐字段打断用户。

每个问题必须说明用途。项目规模、年限、水量、价格、投资、成本、融资、税率、优惠资格、折现率和评价基准不得按行业惯例猜测。缺少融资条件时用 `financing_declaration` 如实声明不可计算，贷款字段不再要求占位；结论保持未决。安全建议也不得自动写回参数文件。

来源方案复现与合同确认必须分开。材料明确写出并实际用于其自身测算的参数、口径或拟议条款，可以按原证据状态进入 `source_declared_baseline`，包括 `proposed_not_binding`；成果必须说明这只是复现来源方案，不代表条款已生效、已核验、获推荐或最优。材料只列为备选、且未进入来源测算的拟议方案继续保持未决。

经营成本按启用路径填写。给出 `annual_amounts_wan` 时不再追问仅供公式路径使用的 `base_wan`、`scales_with_volume` 和 `annual_growth_rate`；调价关闭时可省略 `price_adj_group`；没有副产品收入时可省略 `vat_scope`。融资声明不可用于计算时，不得保留残缺的 `loan_tranches` 或运营期贷款对象。

利润分配政策应一次询问盈余公积计提比例、累计上限比例和分红比例；三者影响股利、留存收益、累计现金、资本金回报和资产负债表，不得以 0 或 100% 代填。

三个字段按实际资料与启用路径处理：`evaluation_date` 缺失时不补固定日期；未给 `base_calendar_year` 时成果只写建设期/运营第 N 年，显式 `base_calendar_year` 仅生成展示年度轴，不成为评价日或政策证据日期，依赖日期的裁决仍保持未决；`revenue.settlement_channel` 缺失时保持未知，不得回填 `direct_from_users`；只有 `sensitivity_deltas` 非空、确需运行敏感性分析时才填写 `sensitivity_target`。

合同按日均计费水量分档时，使用 `revenue.marginal_volume_tiers`：逐档填写累计水量上限和相对当期有效服务单价的倍率，最后一档 `up_to_m3d: null`。它是边际计价，不能把超额档倍率作用于全部水量；合同只写“超额另行计价”但未给阈值或倍率时保持未决，不得启用分档。

`supporting[].as_of` 或 `provided_by` 在原件未载时可写 `null`，但必须填写 `metadata_gap_reason`，且 `evidence_state` 不得标为 `verified`。该证据只能进入待补台账，不能支持确定裁决；禁止用当前日期、转换者名称或“项目单位”等占位值补齐。

## 三阶段工作方式

1. **建模。**先识别固定事实、可协商参数、情景假设和缺失资料，再确定模式、税务口径、融资边界与评价判据。定额、地方价格信息和工程量清单是上游估算依据，必须记录地区、版本日期、调整系数、价税口径和来源；CLI 只接收经确认的投资与成本结果。
2. **迭代。**先跑基准，再用 `sensitivity` 或一维 `solve` 找到关键变量和边界。只有用户已讨论并认可进入比较的方案，才写入 `scheme-set` 运行 `compare`；每个候选必须披露代价、责任方、审批和证据。不得自动搜索参数或调到结论成立为止。
3. **冻结与报告。**用户确认候选后，把其 `resolved_params` 固化为下一版输入，创建新 run 并验证；下游 LLM 结合源资料与该 run 组织正式报告，不得重算或改写裁决。

税务选择只有在法规、适用日期、项目资格和证据均支持时才是合法候选。不得把“税额通常可以抵消”当作事实，也不得仅为降低成本采用优惠口径。

## 十诫式硬规则

1. **不得编造，融资尤严。**融资材料缺失时声明不可用，登记未决且不给融资参数；声明优先于参数，误给的参数也会被忽略并告警。错误示范：用行业惯例补利率、期限或还款方式。→ 后果：资本金、偿债和总体裁决失去依据。
2. **金额口径必须闭合。**逐项识别含税或不含税；资本化建设期利息只分配给合格非流动资产，费用化利息不进入资产原值。全投资评价现金流是否包含资本化建设期利息，按资料明示口径填写 `calculation_basis.project_cashflow_initial_investment`；该选择不改变项目总投资、资金筹措和财务计划。错误示范：把含税总投资整体作为可摊销资产，或为匹配结果擅自剔除 IDC。→ 后果：摊销、利润、所得税及项目回报率均失真。
3. **证据状态如实登记。**保留材料原有的证据等级；摘录、待核、未决不能抬为已核验。错误示范：把来源自报改写为已验证。→ 后果：裁决档位被虚高，补证需求被掩盖。
4. **整份口径声明进入 `declared_basis`。**把合同或方案中的计算口径、例外、取舍和未建模限制完整写入字符串字典；它用于呈现和对照，不改变计算。错误示范：只把一个数字填进参数，省略其适用范围和例外。→ 后果：结果无法追溯到原始口径。
5. **已声明总量进入 `declared_scalars`。**材料明示的汇总金额、比率、目标或基准应逐条登记，并带来源和日期。错误示范：只把总量拆进参数表而不保留原声明。→ 后果：无法对账，汇总口径会在转换中丢失。
6. **基准必须分税前、税后和 target。**登记财务基准时确认其计算对象与税前/税后属性，并让比较目标与材料声明一致。错误示范：把税后目标写入税前槽位，或未标注 target。→ 后果：盈利能力比较方向或结论错误。
7. **表格必须结构化承接。**每张可用数据表使用 `supporting[].table_role`，并以 `value.columns` 与 `value.rows` 保留列和行。错误示范：把表格转成一段叙述或散落数字。→ 后果：表格不能被证据、表图和裁决通道识别。
8. **禁止 JSON 倾倒。**证据、表格和内部载荷只能按契约字段进入，不得把整份 JSON、数组或机器状态塞进叙事文本。错误示范：把原始证据对象序列化为一段正文。→ 后果：报告出现超长机器块并触发 D7-06。
9. **规范必须登记到 `normative_profile`。**文号、名称、日期、要点、适用范围和证据状态按规范登记结构写入。错误示范：把规范名混入普通说明，或把共享底册当成项目证据。→ 后果：规范引用不可核验且证据来源混同。
10. **拿不准先记日志，不要硬填。**契约存在多种合法读法、材料缺值或无对应键时，记录判断、未决或不可转换项，不以占位值冒充事实。错误示范：为通过校验随意选择枚举值或补零。→ 后果：`build` 即使成功，计算链仍可能不成立。
11. **含税建设投资必须译出进项。**题面声明投资额含税且建设期进项按倒算法时，除 `tax_inclusive_no_credit` 外，逐资产写入 `deductible_vat_wan`。错误示范：bt3 漏译导致抵扣字段全零、税基链全偏。→ 后果：摊销原值、所得税、项目税后指标和期末留抵同步失真。
12. **先问缺参，再 build。**参数草稿必须先过 `wwtp-fin intake`；未就绪时按诊断清单向用户批量提问。建议值须标注条件和影响，未经确认不得采用。
13. **冲突不能靠猜。**逐字段按适用性与口径、正式权威状态、明文一致性、生效日期排序；不得仅凭文件类型、新旧日期、出现次数或与缓存结果接近而选值。仍冲突时保持未决并询问用户。
14. **公式必须验证后才能取值。**至少核对公式引用、缓存结果、单位和行列标签；断链、量纲错误或标签矛盾的公式不能反推合同条款。不得从还本表形状推断贷款期限、宽限期或还款方式。
15. **来源基准不是候选方案。**材料明示且实际用于来源测算的参数可按原证据状态进入 `source_declared_baseline`，不等于合同已生效、推荐、最优或用户确认方案；未被来源测算采用的拟议备选仍不得进入。只有依据、责任、代价和审批条件完整的有限方案才可进入 `scheme-set`。
16. **真实逐年还本不得伪造分笔。**原件给出一笔贷款的非均匀本金序列时，使用 `loan_tranches[].principal_repayment_schedule_wan`；其长度等于运营期、合计等于该笔本金，并不得同时填写该笔 `term_years`、`grace_years` 或 `repayment_method`。缺序列时保持融资未决。

## 自检清单

- 已用当前 `schema` 与最小完整示例校验字段、枚举、必填项和跨字段约束。
- `build` 退出码为 `0`，并已逐条消化 `warnings.json`：修正、如实声明或登记未决均有去向。
- `check` 全绿；未决事项没有被计算参数、确定数值或确定裁决反向覆盖。
- 每个金额、基准、表格、规范和证据状态均能回指到材料或转换日志。
- 每个冲突字段都有裁决依据或保持未决；每个公式值已核引用、缓存结果、单位和标签。
- 来源声明基准、候选方案和用户确认方案未混用；没有合法候选时未运行 `compare`。
